# 规格：PDF 布局适配 agent 服务

- 状态：已废弃（2026-09-15 起由 006/007 AI 布局取代，`/api/layout`、`/api/pdf`、`layout_agent.py`、`pdf_render.py` 已删除）
- 创建日期：2026-08-21

## 用户场景

前端把用户编辑好的 JSON 数据提交给后端，后端 agent 不需要人指定模板，而是根据数据的结构特征自动决定版式（表格、列表、键值对、分节），生成一份排版合理的 PDF。

## 功能需求

- FR-1：`POST /api/layout` 接收 `{data, title?}`（或直接接收 JSON 数据），返回布局规格 DocumentSpec（blocks 序列）。
- FR-2：`POST /api/pdf` 接收同样输入，返回 `application/pdf` 文件。
- FR-3：结构 → 版式映射规则：对象字符串字段 → 键值对；同构扁平对象数组 → 表格；字符串数组 → 编号列表；嵌套结构 → 递归分节（标题最多两级）。
- FR-4：PDF 正确渲染中文（A4 页面，表格跨页重复表头）。
- FR-5：前端不提供生成 PDF 入口；`/api/pdf` 保留为纯后端接口，供直接调用或未来功能使用。

## 验收标准

- AC-1：`GET /api/health` 返回 `{"ok": true}`。（对应 FR-1、FR-2）
- AC-2：对包含四类结构的样例数据调用 `/api/layout`，返回的 blocks 与 FR-3 映射一致。（对应 FR-3）
- AC-3：对含中文的样例数据调用 `/api/pdf`，返回合法 PDF（`%PDF` 头），渲染后中文、表格、编号列表显示正常。（对应 FR-4）
- AC-4：`POST /api/pdf` 可通过任意 HTTP 客户端直接调用。（对应 FR-5）

## 非目标（Out of Scope）

- 接入 LLM 做语义级排版决策（当前为规则推导，接口设计为其预留空间）。
- 自定义字体上传、版式模板配置。
- 鉴权、多租户、异步任务队列。
