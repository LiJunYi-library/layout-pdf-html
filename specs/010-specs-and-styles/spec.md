# 规格：图表规范与视觉样式（specs + styles）

- 状态：已实现
- 创建日期：2026-09-18

## 用户场景

运营在布局页和 AI 对话生成 PDF 版式。不同图表共享同一套行为默认值（如环形图默认无 tooltip、无 legend），但不同组织/场景需要不同视觉皮肤（配色、字体、圆角）。把"规范"和"样式"分成两张表存库，布局页提供下拉选择 + 查看/编辑弹窗，agent 生成模板时把两份内容注入提示词。

概念分层（讨论结论）：

- **固定契约**（代码写死，不进表）：A4 尺寸、Jinja2 输出格式、资源白名单。
- **规范 spec**：图表/排版行为默认值（tooltip、legend、数据标注位置等），平台级，通常只有一份或少数几份。
- **样式 style**：视觉主题（配色、字体、圆角、背景），按组织/客户变化。
- 优先级：用户指令 > 规范 > 样式。

## 功能需求

- FR-1：新建 `specs` 表（id, name, content, created_at）与 `styles` 表（同结构），平台级（无 org 维度）。init_db 时各播种一行默认数据（表为空才插）。
- FR-2：`documents` 表增加 `spec_id`、`style_id` 可空外键；为空时 agent 回退到默认行（id 最小者）。
- FR-3：后端 API：
  - `GET /api/specs` / `GET /api/specs/{id}` / `PUT /api/specs/{id}`（name/content 可改）
  - `GET /api/styles` / `GET /api/styles/{id}` / `PUT /api/styles/{id}`（同上）
  - `PUT /api/documents/{id}` 扩展接受可选 `spec_id`、`style_id`（整数校验存在性，null 表示解绑）
- FR-4：agent 组装提示词时注入规范全文与样式全文（【图表规范】【视觉样式】段，置于指标规范之前）；固定契约中声明优先级"用户指令 > 图表规范 > 视觉样式"。
- FR-5：布局页（/layout）对话面板头部增加两个下拉框（规范、样式），选项来自 API，选中值绑定当前文档（改动即 PUT 保存）；每个下拉框旁有"查看"按钮。
- FR-6：点击"查看"打开弹窗：显示名称与内容（可编辑 textarea），底部"保存修改"按钮（朴素样式）PUT 保存；"关闭"按钮样式显眼，点击直接关闭弹窗（不保存）。

## 验收标准

- AC-1：重启后端后 `GET /api/specs`、`GET /api/styles` 各返回至少一行默认数据。（curl 验证，对应 FR-1）
- AC-2：`PUT /api/documents/1` 传 `spec_id`/`style_id` 后，`GET /api/documents/1` 返回绑定值。（curl 验证，对应 FR-2/FR-3）
- AC-3：发一条 agent 对话后，服务端日志/行为确认提示词包含规范与样式内容（可用真实 LLM 一次生成验证模板遵守规范默认值）。（对应 FR-4）
- AC-4：布局页出现两个下拉框与查看按钮；下拉切换后刷新页面绑定保持；弹窗可编辑保存、可关闭。（手动/构建验证，对应 FR-5/FR-6）
- AC-5：`pnpm -C web build && pnpm -C web lint` 通过。

## 非目标（Out of Scope）

- 不做规范/样式的新建、删除（运营初期只编辑默认行）。
- 不做 org 维度私有规范/样式。
- 不做下拉框以外的文档列表页改动。
- 规范内容不进 fake-oss（文本小，直接存库表 content 字段）。
