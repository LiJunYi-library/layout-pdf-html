# 规格：首页文档列表与编辑器路由调整

- 状态：已实现
- 创建日期：2026-08-21

## 用户场景

用户打开应用首先看到已保存的文档列表（来自 documents 表），了解已有内容；需要编辑 JSON 数据时进入 `/data` 页面的编辑器。

## 功能需求

- FR-1：首页路由 `/` 改为文档列表页：调用 `GET /api/documents`，以表格展示 `id`、`title`、`data_id`、`created_at`；有加载与错误状态。
- FR-2：JSON 数据编辑器从 `/` 移到 `/data` 路由，功能不变。
- FR-3：顶部导航包含：文档（`/`）、数据编辑（`/data`）、布局预览（`/layout`），当前页高亮。
- FR-4：布局预览页不提供「返回编辑」按钮，页面间导航统一走顶部导航栏。
- FR-5：文档列表每行提供两个操作按钮：
  - 「去布局」：跳转 `/layout?documentId={文档ID}`。
  - 「绑定数据ID」：输入数据 ID 后调用 `PUT /api/documents/{id}` 更新绑定，成功后刷新列表；ID 非正整数时给出提示。
- FR-5a：`/layout` 携带 documentId 时，调用 `GET /api/documents/{id}` 取回文档详情（含关联 data），用该数据请求 `/api/layout` 并以文档标题作为布局标题渲染；页面展示文档信息（标题、文档 ID、数据 ID）；加载与错误状态可见。未携带 documentId 时保持原有编辑器数据预览行为。
- FR-6：文档列表每行提供「修改数据」按钮，跳转 `/data?dataId={数据ID}`。
- FR-7：`/data` 携带 dataId 时，调用 `GET /api/data/{id}` 取回数据并渲染到 JSON 编辑器；加载与错误状态可见。
- FR-8：`/data` 提供保存功能：已带 dataId 时 `PUT /api/data/{id}` 全量更新；未带 dataId 时 `POST /api/data` 新建并切换到新 dataId；成功与失败均有反馈。

## 验收标准

- AC-1：`pnpm -C web build && pnpm -C web lint` 通过。（对应 FR-1~FR-4）
- AC-2：访问 `/` 显示文档列表，内容与数据库 documents 表一致。（对应 FR-1）
- AC-3：访问 `/data` 显示 JSON 编辑器，功能与调整前一致。（对应 FR-2）
- AC-4：三条导航均可达且当前页高亮正确。（对应 FR-3）
- AC-5：`pnpm -C web build && pnpm -C web lint` 在新增按钮后仍通过；「去布局」「绑定数据ID」交互在浏览器实测。（对应 FR-5）
- AC-6：从列表点「修改数据」进入 `/data?dataId=N`，编辑器渲染出与数据库一致的内容；修改后保存，GET `/api/data/N` 返回新值。（对应 FR-6~FR-8）

## 非目标（Out of Scope）

- 文档列表的新建/删除操作。
- 分页、搜索、排序。
